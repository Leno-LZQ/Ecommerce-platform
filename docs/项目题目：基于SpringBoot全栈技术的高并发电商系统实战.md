# 项目题目：基于 Spring Boot 全栈技术的高并发电商系统实战

## 一、项目定位

**不是"大而全的技术罗列"，而是"多而不虚的实战落地"。**

每个引入的技术都有明确的业务场景支撑，拒绝为了用而用。项目规模控制在单人 4~6 周可完成的范围内，同时保留充足的技术深度用于答辩展示。

## 三、架构设计

```
┌────────────────────────────────────────────────────┐
│                   前端层 (Vue 3)                     │
│   管理后台 · 商品浏览 · 购物车 · 订单查询           │
└──────────────────────┬─────────────────────────────┘
                       │ HTTP/JSON
┌──────────────────────▼─────────────────────────────┐
│               网关 (Spring Cloud Gateway)           │
│          路由转发 · 统一鉴权 · 跨域处理             │
├──────────────────────┬─────────────────────────────┤
│       注册中心 Nacos  │  配置中心 Nacos             │
├────┬────┬────┬────┬──┴──┬────┬────┬────┬────┬──────┤
│用户│商品│购物│订单│支付 │搜索│库存│推荐│后台│      │
│服务│服务│车   │服务│服务 │服务│服务│服务│服务│      │
├────┴────┴────┴────┴─────┴────┴────┴────┴────┤      │
│               Redis 集群 (缓存+分布式锁)             │
├──────────────────────┬─────────────────────────────┤
│              MySQL (主库) + ES (搜索)              │
├──────────────────────┴─────────────────────────────┤
│   RabbitMQ (消息队列) · Sentinel (限流熔断)        │
├────────────────────────────────────────────────────┤
│   Docker Compose (容器化) · GitHub Actions (CI)    │
│   Actuator + Prometheus + Grafana (监控)           │
└────────────────────────────────────────────────────┘
```

> **注意**：上述微服务拆了 9 个模块，但这是"逻辑拆分"。实际实现时，这些服务可以按**业务领域分组**放进同一个 Spring Boot 进程的不同包结构中，仅在关键边界（用户/商品/订单）明确拆分为独立模块，然后用 Feign 调用。这样既演示了微服务设计思想，又避免了 9 个独立进程导致的运维灾难。

## 四、业务模块详细设计

### 模块 1：用户服务 (user-service)

| 功能 | 涉及技术 |
|------|---------|
| 注册/登录 | Spring Security + BCrypt + JWT |
| RBAC 权限 | @PreAuthorize 注解、角色/权限表设计 |
| 用户行为日志 | AOP 切面 + RabbitMQ 异步写入 |
| 登录限流 | Sentinel 热点参数限流（按 IP） |

**技术深度点**：
- JWT 双 Token（Access + Refresh）机制
- 密码加密与防暴力破解策略

### 模块 2：商品服务 (product-service)

| 功能 | 涉及技术 |
|------|---------|
| 商品 CRUD | MyBatis-Plus |
| 商品搜索 | Elasticsearch + IK 分词 + 高亮 |
| 热门商品缓存 | Redis ZSet（按访问量排序） |
| 商品详情缓存 | Redis Hash + 缓存预热(@PostConstruct) |
| 库存扣减 | Redis Lua 脚本保证原子性 |

**技术深度点**：
- 数据库与 ES 双写一致性方案（MQ 异步同步）
- 缓存穿透（布隆过滤器）/ 击穿（互斥锁）/ 雪崩（随机过期时间）完整方案
- 库存扣减的 Lua 原子脚本

### 模块 3：购物车服务 (cart-service)

| 功能 | 涉及技术 |
|------|---------|
| 购物车 CRUD | Redis Hash（用户维度存储） |
| 购物车合并 | 登录时临时购物车与持久购物车合并 |

**技术深度点**：
- Redis 存储购物车的选型原因（高性能、非结构化）

### 模块 4：订单服务 (order-service)

**技术深度点**：
- RabbitMQ 延迟队列的两种实现对比（插件 vs TTL+DLX）
- 接口幂等性的三种方案对比

### 模块 5：支付服务 (payment-service)

## 五、关键技术深度点（答辩重点）

### 5.1 Redis 缓存三大问题

| 问题 | 方案 | 演示方式 |
|------|------|---------|
| 缓存穿透 | 布隆过滤器（Guava BloomFilter） | 查询不存在的商品 ID |
| 缓存击穿 | 互斥锁（Redisson Lock） | 热点 Key 过期瞬间高并发请求 |
| 缓存雪崩 | 随机过期时间 + 多级缓存 | 大量 Key 同时失效模拟 |

### 5.2 分布式锁

- **场景**：库存扣减、下单防重
- **方案**：Redisson `RLock`（看门狗自动续期）
- **对比**：数据库锁 → Redis SETNX → Redisson → ZooKeeper

### 5.3 分布式事务

- **场景**：下单 → 扣库存 → 扣余额 → 生成订单
- **方案**：RabbitMQ 可靠消息最终一致性（本地消息表 + MQ 重试）
- **演示**：下单后立即取消订单，验证库存回滚

### 5.4 接口幂等性

- **场景**：用户快速双击下单按钮
- **方案**：Redis Token + 数据库唯一索引
- **演示**：JMeter 并发 100 个相同请求，只生成 1 个订单

### 5.5 消息队列实战

- **延迟队列**：30 分钟未支付自动取消订单
- **死信队列**：支付回调失败后的重试与最终处理
- **削峰填谷**：秒杀场景下单请求先入队列再异步处理

### 5.6 容灾与限流

- **限流**：Sentinel QPS 限流 + 热点参数限流
- **熔断**：Sentinel 熔断降级（商品服务不可用时走缓存）
- **兜底**：Hystrix 级别的 Fallback 策略
