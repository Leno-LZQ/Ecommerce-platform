## 三、核心洞察：生产级 ≠ 部署到哪

### 3.1 误解澄清

> 很多人认为"生产级 = 部署在云上 + 多副本高可用"。  
> 但实际上，**生产级是一套软件工程标准**，与部署目标无关。

## 四、技术可行性分析

### 4.1 内存可行性

全量方案在本地 16GB 开发机上的内存分布：

| 层级 | 组件数量 | 内存占用 |
|:-----|:------:|:--------|
| 中间件层（MySQL/Redis/RabbitMQ/Nacos/Nginx） | 5 | ~1.3 GB |
| 业务层（9 个微服务） | 9 | ~2.0 GB |
| 前端层 | 1 | ~0.03 GB |
| 可观测性层（ELK/Prometheus/Grafana） | 5 | ~1.2 GB |
| **全量合计** | **20** | **~4.5 GB** |
| 纯业务（不含可观测性） | 15 | ~3.3 GB |
| 极简（仅核心 5 服务 + 中间件） | 10 | ~2.0 GB |

> 16GB 开发机轻松承载全量方案。8GB 机器关闭可观测性后同样可用。

### 4.2 开发体验

- **全量启动耗时**：60-90 秒（`docker compose up -d`）
- **日常开发**：只启动需要的服务（如只写 user-service，启动 MySQL+Redis+Nacos+user-service，< 30 秒）
- **CI/CD**：全部在 GitHub Actions 云端运行，本地零负担

### 4.3 单节点容错

| 故障类型 | 恢复机制 | 恢复时间 |
|:---------|:--------|:-------:|
| 微服务 OOM 崩溃 | `restart: unless-stopped` | < 30s |
| MySQL 进程崩溃 | 同上 + InnoDB 自动恢复 | < 30s |
| Redis 崩溃 | 同上 + AOF 持久化恢复 | < 15s |
| Docker daemon 崩溃 | systemd 自动拉起 | < 10s |

## 五、升级内容概要

### 5.1 十大升级维度

| 维度 | 课程级 → 生产级 | 主要工具/手段 |
|:-----|:---------------|:-----------|
| **代码质量** | 无标准 → 多维度自动化检查 | Checkstyle + SpotBugs + SonarQube |
| **测试体系** | 零覆盖 → 四层测试 ≥80% | JUnit5 + Testcontainers + Contract + E2E |

| **安全加固** | 无 → 多层级防护 | JWT(RS256) + RBAC + 限流 + 加解密 |
| **可观测性** | println → 三维度统一 | ELK + Prometheus + Grafana + SkyWalking |
| **可靠性** | 无 → 多层兜底 | 限流 + 熔断 + 降级 + 自愈 |
| **性能** | 无 → 三级缓存 + 异步 | Caffeine + Redis + MQ + Lua |
| **数据管理** | 无 → 全生命周期 | Flyway + 备份 + 归档 + 慢查询 |
| **业务闭环** | 基础 CRUD → 可运营 | 支付 + 售后 + 运营后台 + 优惠券 |

| 维度 | 保持方式 | 原因 |
|:-----|:--------|:-----|
| **部署复杂度** | `docker compose up -d` 一键启动 | 降低门槛，聚焦工程质量 |
| **高可用架构** | 单节点 + `restart: unless-stopped` | 本地开发不需要多副本 |

## 十、总结

- 部署保持 `docker compose up -d`（课程级）
- 代码达到 Checkstyle + SonarQube + 80% 测试覆盖率（生产级）
- CI/CD 全自动，质量门禁不通过则无法合并（生产级）
- 安全审计、日志监控、限流熔断全部就位（生产级）
- 成本 ¥0/月（本地），随时可 10 分钟上云（¥195/月）
